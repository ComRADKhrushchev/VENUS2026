**Terminology in this document** (annotated at first use):
- **Roster**: the table describing the system's composition — each atom's element symbol, mass, and fragment
  membership, plus fragment geometry and unit-cell parameters. Hosted in config_roster.f90.
- **Physical-state variables** (called the "thing-in-itself" in the spec): irreducible physical variables —
  coordinates Q, momenta P, electronic state s, forces F. Hosted in state.f90.
- **Freezing operations** (spec §3.1): moving system prescriptions from code into data — functionally bounded
  families (nuclear propagators, electronic methods, etc.) are pre-written as closed selections, chosen via
  input data.
- **Registry-family members**: swappable implementations attachable by "new file + one registration line"
  (pes_* potential members, dist_* initial-state distribution members). **A member = code + its own data.**

**Goal:** rebuild the minimal declarations of the four L1 modules. The representation zone's organization follows
the spec §3.2 decomposition: **① control-flow must-haves** (an independent module control.f90) + **②
observables** + **③ the four kinds of input prescriptions derived from the interface freezing operations**
(nuclear propagator / electronic space–electron propagation law / reactants / events); the latter are wrapped in
types, and concrete variables not yet determined are **left blank** (comment placeholders, not declared dead).

**Deliverables:**
1. `src/consts.f90` / `src/state.f90` / `src/control.f90` / `src/config.f90`
2. §2 legacy cross-reference index (for Phase C reference)
3. Commit `K1: global variables minimal set (state/config/control/consts, reorganized by spec reasoning)`

**Design decisions:**

D1 **state uses a derived type**, held by the driver (main program) and passed as an argument — consistent with
the facade signature (Q,P,s)→(F,E), argument style.
D2 **Derived quantities and integrator workspaces do not go into state** (velocities = P/mass etc. belong inside
the propagator).
D3 **Masses belong to the roster** (config_roster.f90, skeleton built in K2).
D4 **The representation zone's organization is derived from the spec** (user ruling 2026-09-06): control flow /
observables / freezing-derived prescriptions (type-wrapped); no arbitrary partitioning. **Control flow is its own
module control.f90** (rationale: spec §2.2 — the control kernel holds no physics knowledge; its input variables
(task, trajectory count, seed, title) are kept separate from the physics prescriptions; the main program only uses
control, and physics modules do not reference it).
D5 **Type wrapping + blanks**: one derived type per prescription category; determined variables are declared as
they are, undetermined ones are left blank as comments (stating who will fill them in and when); no fake
declarations.
D6 **Naming convention**: recognizable short abbreviations, lowercase underscore-separated segments, each
segment 1-6 characters, conventional single letters preferred; a Chinese comment per line (meaning + units).
D7 **Minimal-set principle**: keep only the fewest variables needed to support the framework; missing items are
introduced in Phase C by their consumers as needed; dead variables (those with no consumers in the legacy tree)
never enter.

### 1.2 src/state.f90 (physical-state variable container, as in v4)

```fortran
module state
  implicit none
  private
  public :: elec_t, state_t, state_create, state_destroy
  type :: elec_t          ! Electronic state s (runtime): adiabatic = degenerate point (single surface)
     integer :: n_surf = 1   ! Number of potential surfaces
     integer :: i_surf = 1   ! Current surface index
  end type
  type :: state_t
     integer :: natoms = 0   ! Number of atoms (set at runtime from the roster)
     integer :: ndof   = 0   ! Degrees of freedom = 3*natoms
     real(8), allocatable :: q(:) ! Coordinates [Å]
     real(8), allocatable :: p(:) ! Momenta [amu·Å/(10 fs)]
     real(8), allocatable :: f(:) ! Forces [internal energy/Å]
     type(elec_t) :: s
     real(8) :: t = 0.0d0     ! Trajectory time [10 fs] (held by the main program)
  end type
end module
```

### 1.4 src/config.f90 (representation layer: observables + freezing-derived prescriptions, type-wrapped)

```fortran
module config
  implicit none
  private
  public :: propagator_t, electronic_t, reactants_t, event_t, observables_t
  public :: propagator, electronic, reactants, event, observables

  ! ===== Input prescriptions derived from the freezing operations (spec §3.1-3.2) =====

  ! Nuclear propagator (spec §3.2-1: functionally bounded, frozen as a closed family)
  type :: propagator_t
     integer :: id    = 1     ! Integrator number (verlet/symple/radau, a closed three-member family)
     integer :: order = 0     ! Order/variant parameter
     real(8) :: dt    = 0.01d0 ! Step size [10 fs]
     ! Blank: adaptive step-size bounds dt_min/dt_max (introduced at RADAU concretization, C6)
  end type

  ! Electronic level (spec §3.2-2: two independent axes — H-representation capability level × electron propagation law)
  type :: electronic_t
     integer :: method = 1       ! Electron propagation law (1=adiabatic degenerate point; nonadiabatic reserved)
     integer :: n_surf  = 1      ! H-representation capability level (single surface; multi-surface/coupling deferred to nonadiabatic)
     character(len=32) :: pes_main = ''  ! Main potential member name (H-field provider, interface A)
     ! Blank: additive force-member table (GLO spring/Langevin ghost/LDFA — introduced with the facade in C2);
     !       dielectric/external-field and other capability-level extensions
  end type

  ! Reactant prescriptions (spec §3.2-3: configuration prescriptions + initial-state statistical distributions, both input data)
  type :: reactants_t
     integer :: n_frag = 1           ! Number of fragments
     integer :: surface_model = 0    ! Configuration paradigm (0=gas phase; 1/2=the two surface paradigms)
     integer :: dist_scheme(2) = 0   ! Sampling scheme per fragment (pointing at dist_* members)
     real(8) :: e_rel  = 0.0d0       ! Collision energy (relative-motion distribution) [kcal/mol]
     real(8) :: b_max  = 0.0d0       ! Maximum impact parameter [Å]
     real(8) :: r_sep  = 0.0d0       ! Initial separation [Å]
     ! Configuration details (roster/geometry/cell) are carried by config_roster (K2 skeleton);
     ! Blank: orientation prescriptions, per-fragment distribution parameters — carried by the dist_* members
     ! themselves (member = code + data)
  end type

  ! Event prescriptions (spec §3.2-3: termination predicates + outcome classification, data not code)
  type :: event_t
     character(len=256)  :: term_expr   = '' ! Termination predicate expression (wired in C3)
     character(len=1024) :: outcome_tbl = '' ! Outcome classification table (wired in C7)
     ! Blank: event-category extensions (constraint windows/multi-event coupling — filled in when the predicate
     ! grammar is finalized)
  end type

  ! ===== Observables (generic energy terms and recording settings) =====
  type :: observables_t
     integer :: rec_level = 2          ! Recording verbosity (preset column groups)
     character(len=256) :: obs_list = '' ! Observable column list (C4 recorder column registration)
     logical :: e_kin = .true.         ! Kinetic energy T (generic energy term)
     logical :: e_pot = .true.         ! Potential energy V (generic energy term)
     logical :: e_tot = .true.         ! Total energy H (generic energy term)
     ! Blank: more observables extended with recorder column registration (angular momentum, local quantities, etc., C4/C8)
  end type

  type(propagator_t) :: propagator
  type(electronic_t) :: electronic
  type(reactants_t)  :: reactants
  type(event_t)      :: event
  type(observables_t) :: observables
end module
```
