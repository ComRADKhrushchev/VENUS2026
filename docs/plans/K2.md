comments); ② a pseudocode body (imperative steps, aligned with the legacy provenance; executable implementations
forbidden); ③ a provenance comment (`! Reference: legacy file:line`).
E2 **Members carry their own parameters**: the dist example skeletons declare parameter derived types (blank
fields allowed, commented "settled in Phase C").
E3 **Slimming ruling (user, 2026-09-06)**: pes_* deferred to C2; dist_* keeps only 3 examples
(boltzmann/ebk/incident — covering the two shapes of distribution-member prototype and incident channel), and
**without sample routines** (only init + params skeletons); the sampler.f90 framework stays (the B′ framework
slot, the samp_run pseudocode annotated "distribution member table filled at C5").
E4 **K1 reverse check**: the skeleton uses only the four K1 modules; a missing global variable = skeleton drift,
recorded in a list and taken back to the review gate.
E5 **The Makefile is untouched**: K3 fills in SRC + the stub main program + the whole-tree compile.
E6 **Batch execution**: 4 batches (L5+roster / closed families+facade / dist examples / L4+L0+input), each batch
one implementation dispatch + quick review, one overall review at the end of K2.
E7 **driver skeleton**: a program placeholder, three-phase pseudocode (assembly→evolution→statistics); inside
the evolution loop only facade/propagator/recorder/predicate are called (spec §2.5 phase restriction).
E8 **Directory organization (user ruling 2026-09-07, settled at the third revision)**: directory names drop the
layer tags and take formal names; the root keeps only the two entry pieces driver.f90/input.f90; the five
variable-and-prescription pieces go into globals/; the closed families (predicate/propagator) go into dynamics/;
the registry-family member directories take the interface_ prefix, two houses — interface_electronic/ (spec
§3.2-2: the electronic level's two axes live in one house: the class-A pes_* H-field providers land here in C2 +
the class-B elec_* electron propagation laws, elec_adiabatic first, IESH to join later; axis separation is
guaranteed by module independence + the reg_pes/reg_elec dual registry + capability-level negotiation) and
interface_distributions/ (B′ initial-state distributions). The L0-L5 layer concept stays in the doc-level
mapping table and is not carried into directory names.
E9 **Multi-surface PES interface upgrade (user ruling 2026-09-07: upgrade immediately + dual signatures
coexisting + upgrade the whole package in one go; the outcome of the four-scenario thought experiment)**: the
class-A dual signatures coexist — pes_diab_i (diabatic H_ij+∇H_ij, the natural form of the IESH model
Hamiltonian; the adiabatic view computed on the fly via utils/linalg diagonalization) / pes_adiab_i (adiabatic
per-surface V_i/forces + the derivative-coupling row of the current surface — only the current surface at
O(ndof·n_surf), recomputed on the new surface after a hop), with the single-surface scalar signature pes_proc_i
kept as-is (the six C2 single-surface members untouched; additive semantics unchanged; the multi-surface main
potential is not additively composed, and additive scalar members enter only the core-force channel). The
class-B signature gains dt (elec_proc_i(s, f, dt) — hop probabilities g_ij(dt) depend on the step size; the
adiabatic member ignores it). elec_t gains the electron amplitudes amp(:) (|c_i|²=populations) and the hop count
n_hop (nonadiabatic observables; adiabatic degenerate point = single element, constant 1 — well-definedness
preserved; state_create gains an optional n_surf). The capability-level negotiation is made data: the triad_tbl
with four rows (the current single-surface adiabatic + multi-surface tsh/iesh pre-authorized — an empty class-B
registration slot is caught by the facade_init loud-stop, a double gate; **the radau entry is permanently false
in the multi-surface rows** — an adaptive sequence's "one step" is not well defined). Touches state.f90 (real
implementation) and force_facade.f90 (real code for interfaces/tables + routine pseudocode); the related
comments in elec_adiabatic/propagator/driver updated in sync; the degenerate-equivalence verification
(n_surf=1 bit-level identical with the scalar channel, the same criterion as N1.1) executes when the C2 pes
members land.
E10 **Workspace-mode revision (user ruling 2026-09-07: independent module elec_ws + a fully unified single
signature + comment-level legislation with field names unchanged — the axiomatic correction of E9,
"representation constructs do not have thing-in-itself status")**: three axioms legislated — A interface
invariance (the abstract interface is invariant for both system and representation: the signature passes only
the container ws_t, never shape arrays like h_ij/d_ij; E9's pes_diab_i/pes_adiab_i dual signatures and the
i_surf argument are withdrawn — representation and electronic-state knowledge stay out of the class-A
signature); B black-boxness (class-A + class-B merge into one system black box — outside the box one sees only
(Q,P,s[,dt])→(F,E), the facade_force signature unchanged; ws is a facade-local variable, declared inside the box
and dying inside it); C the thing-in-itself principle (representation constructs like H_ij/d_ij/V_i enter
neither state_t nor the outside of the box; lifetime is one step). Landing pieces: add facade/elec_ws.f90 (a
zero-dependency contract module — the ws_t container + the r_empty/r_scalar/r_diab/r_adiab fill-mode markers;
i_surf communicated via the request field ws%i_want); the force_facade class-A signature fully unified as
pes_proc_i(q, mass, ws) (intent(inout) — the facade pre-writes the request fields, the member fills the delivery
fields), registration via the single entry point facade_reg_pes(name, proc[, repr]) (default r_scalar — the six
single-surface members' registration lines untouched; E9's dual registration routines facade_reg_pes_diab/adiab
deleted); the class-B elec_proc_i(s, f, dt, ws) (ws consumed read-only; a repr the member does not support →
loud-stop); the triad_tbl pes_kind column's semantics changed to the ws fill mode (the four-row table data
unchanged); the facade_force pseudocode unified onto the ws fill-mode path (the multi-surface force-core
construction demoted to a note on branch 4'). The state.f90 elec_t comment legislation: amp(:) promises only a
complex array; index semantics (surface representation i=surface number / one-electron representation
i=electron×state tensor-product flattening / configuration representation i=configuration number) are defined by
the class-B method member — the field name is unchanged. The elec_adiabatic adapter's comment gains "ignores dt
and ws". The degenerate-equivalence verification criterion carries over from E9 (executed at C2).
E11 **Drag-in blackbox build legislation (user ruling 2026-09-08: legislate "drag in and it works" +
the registration marker = a folder-bundled reg file)**: the system-specific information of interface A
is packaged as a standalone folder (systems/<system>/ — member files plus one thin reg module
reg_<system>_all() holding that system's full set of registration lines
facade_reg_pes/facade_reg_elec/samp_reg...). The K3 build criteria are thereby fixed: (1) SRC wildcard
pickup of the systems/ subtree ($(wildcard) — drag in and it compiles; the Makefile never changes
again; .mod dependencies let make sort the compile order); (2) a prebuild script scans
systems/*/reg_*.f90 and generates registry_gen.f90 (the call sequence aggregating the reg entry
points), and the driver assembly phase calls only the fixed point registry_gen_all() — registration
becomes a build artifact; the body (driver/force_facade/propagator...) is untouched. The T2 criterion
is upgraded: a new system = a new folder (with its own reg), no longer "new file + one registration
line in driver". Constraints and semantics: Fortran has no reflection/static constructors — the exact
meaning of "zero registration" is that registration is demoted from hand-written code to a
build-generated artifact (after dragging in, a fresh make picks it up); the reg module naming rule
reg_<system>_all prevents clashes; triad_tbl stays in the facade (capability-level legality is
facade-domain knowledge — a new combination = table data, not code). The K2 skeleton's driver
registration pseudocode stays as the transitional form; E11 takes effect at K3.
E12 **Single-layer self-contained blackbox, system-vs-generic variable audit (user ruling 2026-09-08:
no generic method-skeleton directory — each blackbox folder carries its own complete members)**:
premise — the program splits into system-specific code (the system blackbox) and physics-generic
code; a full audit of module-level and routine-local variables asks "is this system-specific?", with
the verdict that anything system-specific must not live in the generic code. Audit results:
(1) the facade locals are all generic — the ws container is a system-invariant shape whose
system-specific *content* is filled at runtime by blackbox members and dies in one step (never
resides in generic code as knowledge); sampler/dist framework, registries, triad_tbl, unit-contract
constants likewise generic; (2) one data-level violation found and fixed — config_roster's a_lat
carried the old-library Au default 2.94998 Å (venus_data.f90:585) as the *generic* type default:
now 0.0 with a roster_load validation loud-stop (surface paradigm + a_lat<=0 names the missing
lattice constant); mass ~1d30 (rigid-surface paradigm knowledge) and box_pad=2.0 (generic geometry)
stay; (3) statute gaps closed in comments — state.f90 n_surf/i_surf representation semantics
(single-electron representation: configuration-space cardinality / current electron-configuration
index, defined by the class-B member, field names unchanged); force_facade branch 4'a notes the
U-delivery tension (ws adiab-view cache field vs class-B re-diagonalization at double O(n_surf^3),
fixed in phase C with elec_tsh). Directory ruling (amends E9's "both axes in one home" for class A):
no generic method-skeleton directory — the planned "interface_electronic/ hosts the six
parameterless pes_* skeletons, systems/ hosts parameterized instances" two-layer scheme is rejected;
each systems/<system>/ folder carries complete members (self-contained functional form + parameters,
copy-and-modify friendly; accepted cost: method code duplicates across systems — decoupling wins).
interface_electronic/ remains the class-B home only (elec_* propagation laws are parameter-free
generic algorithms — adiabatic degenerate member now, tsh/iesh later); interface_distributions/
likewise stays generic (dist_* members take parameters via config at runtime, zero embedded system
data). C2 consequence: pes members are built as self-contained members of example systems (the "six
pes_* files land in interface_electronic/" plan of E3 is superseded); the facade itself is untouched.
E13 **Formal-facade revision, triad_tbl withdrawn (user ruling 2026-09-08: physical-combination
correctness is the blackbox author's judgment - hard limits in the program are meaningless, since
the author is assumed to know the system, not the program)**: the facade's role is to further
prescribe the blackbox's FORM (signature/unit/container contracts, name->pointer dispatch) - nothing
more. The blackbox machine does three things (legislated wording): compute forces from the state
(class A); evolve the electronic state from the current one (class B); feed the electronic state
back into the state to enforce quantum statistics (class B - surface switching, momentum rescaling,
as in TSH). facade_force is the orchestration of the three. Consequence: triad_tbl and the
m_adiabatic/m_tsh/m_iesh method codes are withdrawn from force_facade - its rows (tsh needs fixed
steps, iesh consumes the diabatic container, multi-surface excludes radau) are the class-B members'
implementation knowledge and live inside them: a member loud-stops on a ws%repr it does not support
(E10 contract, unchanged) and on dt semantics it cannot live with (shape fixed in phase C with
elec_tsh - open point: runtime first-step dt comparison vs a member-declared prerequisite flag; no
structure pre-built at K2). This also repairs a latent collision with E11 drag-in: a new
combination would otherwise require editing force_facade to add a table row. config%electronic%
method becomes a name string ('adiabatic', same form as pes_main) - assembly is uniformly
name-lookup. Assembly-time checks kept in facade_init are purely formal: names resolve, the
main-PES slot is filled, additive members are r_scalar (the additive channel of the container is
scalar by construction), n_surf >= 2 with an r_scalar main PES loud-stops (derivable from the
container contract alone). Touches force_facade (table + facade_init/facade_info pseudocode +
header note), config.f90 (method field), propagator header note, the two READMEs, and the master
plan §5 N1 negotiation clauses.
