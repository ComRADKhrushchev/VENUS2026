**Goal:** the new tree builds by a single `make` (gfortran AND ifx), registration becomes
a build artifact (the prebuild-generated registry_gen.f90), and the upgraded drag-in
criterion (T2: a new system = a new folder, zero edits to existing files) is verified by
drill. **K3 is the last skeleton-phase step; Phase C (concretization) follows.**

**Already-earned credit (the K2 compile gates):** every K2/E15-E19 commit closed with a
whole-tree gfortran compile of all units in a clean temp dir (28 -> 27 -> 26 units as
E18/E19 withdrew predicate.f90 / outcome.f90), and E14 closed with the dual-compiler
verification (gfortran + ifx 2025.2, `-r8 -double-size=64 -i8 -O2 -w`). Interface
consistency is therefore already machine-checked; K3's job is to turn the ad-hoc
clean-dir retry loops into the Makefile itself + land the prebuild aggregation (the K2
open point "the prebuild aggregation itself" — the driver still wires reg_adiabatic_all()
transitionally in its step-6 pseudocode).

**Deferral list (unchanged, restated):** all member implementations -> Phase C (C2 pes
members + the container example with its three bindings, C5 dist sample routines);
systems/ holds no real container until C2 — K3 drills with a throwaway folder only.

**Deliverables:**
1. `src/Makefile`: SRC wildcard pickup (`src/*.f90`, `src/*/*.f90`, the future `systems/`
   subtree), .mod-dependency compile ordering (make sorts the order — no hand-maintained
   SRC list, E11), the ifx Windows platform section (ported per venus2026/CLAUDE.md

2. `scripts/prebuild_registry.sh`: scan `src/methods/` and `systems/` for `reg_*.f90`;
   emit `build/registry_gen.f90` (a thin aggregate module whose `registry_gen_all()`
   calls every `reg_<x>_all` entry point in deterministic order); make invokes it
   automatically (first build + whenever the reg-file set changes).
3. Driver transition-wiring withdrawal: assembly step-6 pseudocode's transitional
   `reg_adiabatic_all()` call becomes `registry_gen_all()`; the driver's final form has
   zero hand-written registration lines (E11 end state).
4. Drag-in drill (the T2 upgraded criterion, throwaway): a dummy folder
   `systems/_drill_/` (a reg module performing the three container_bind_* calls on no-op
   members) -> fresh `make` picks it up (wildcard), registry_gen aggregates it, `git
   diff` confirms zero edits to existing files -> drill folder deleted, the record kept
   in the K3 ledger note.
5. K3 checkboxes closed + Notion K3 row update.

**Design decisions (carried rulings, no new adjudication needed):**
- E11: `$(wildcard)` pickup — the Makefile never changes again; .mod dependencies let
  make sort the compile order. Fortran has no reflection/static constructors —
  "zero registration" means registration demoted from hand-written code to a
  build-generated artifact (a fresh make picks a dragged-in folder up).
- E14/E17-E19: the reg file is the atomic registration unit; the aggregation surface =
  methods/ reg_*.f90 (method packages: method_reg) + systems/ reg_*.f90 (the
  container's three single-slot bindings: container_bind_pes / container_bind_term /
  container_bind_classify). pred_reg_prim is withdrawn (E18) — nothing else registers.
- E5: K2 left the Makefile untouched on purpose; K3 owns it from zero.

**Acceptance:**
1. `make` from clean passes BOTH compilers (gfortran; ifx with the conventional flags);
2. registry_gen.f90 regenerates when the reg-file set changes (add/remove -> rebuild);
3. the drag-in drill: the new folder is picked up with ZERO edits outside it (git diff
   empty) and the build stays green — T2 verified;
4. driver.f90 carries zero hand-written registration lines (grep `reg_` in driver.f90 ->
   only the registry_gen call + historical comments);
5. the withdrawn units stay absent (26 units; no predicate/outcome resurrection);
6. K2.5's reverse-check posture preserved: no new module-level state enters (the build
   artifacts are stateless).

**Risks:**

  mitigated by the isolated build/ directory;
- the drill folder matching the wildcard forever — underscore-prefixed name, deleted
  after the drill, the record kept in the ledger.
